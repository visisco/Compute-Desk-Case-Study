Quickstart

Place your first order in the sandbox in about five minutes. Sandbox uses play money and resets every Sunday at 00:00 UTC.

  1. Create a sandbox key. In the platform, open Integrate → API keys, choose Sandbox, and give the key the read and trade scopes. Copy the secret now: it's shown once.
  2. Find a contract. List the H100 US futures and pick a month.
    GET /v1/instruments
    curl -s "https://api.sandbox.computedesk.example/v1/instruments?root=H1UF&status=open" \
  -H "Authorization: Bearer $CDX_KEY" \
  -H "X-Timestamp: $TS" -H "X-Signature: $SIG"
    from cdx import Client   # thin wrapper that signs requests
cdx = Client(key="ck_sbx_…", secret="…", env="sandbox")
for i in cdx.get("/v1/instruments", root="H1UF", status="open")["data"]:
    print(i["symbol"], i["last_trading_day"])
  3. Place a limit order. Buy 8 December contracts (one node-month) at $2.90.
    POST /v1/orders
    curl -s -X POST https://api.sandbox.computedesk.example/v1/orders \
  -H "Authorization: Bearer $CDX_KEY" -H "X-Timestamp: $TS" -H "X-Signature: $SIG" \
  -H "Idempotency-Key: 0b9d4c1e-qs-001" -H "Content-Type: application/json" \
  -d '{"symbol":"H1UFZ26","side":"buy","qty":8,"type":"limit","price":"2.90","tif":"gtc","client_order_id":"qs-001"}'
    order = cdx.post("/v1/orders", json={
    "symbol": "H1UFZ26", "side": "buy", "qty": 8,
    "type": "limit", "price": "2.90", "tif": "gtc",
    "client_order_id": "qs-001",
}, idempotency_key="0b9d4c1e-qs-001")
print(order["order_id"], order["status"])
  4. Watch it fill. Subscribe to your orders and fills channels on the WebSocket, or poll GET /v1/orders/{order_id}.

Authentication

REST and WebSocket use an API key plus an HMAC-SHA256 signature on every request. FIX uses the same key, signed at logon.

API keys and scopes

Create keys in Integrate → API keys. Each key belongs to one account and one environment, and carries only the scopes you give it. Your FCM's pre-trade credit limits apply on top of every key.

ScopeAllows
readReference data, your orders, fills, positions and statements
tradePlace, change and cancel orders; mass cancel
rfqCreate, quote and accept Block RFQs and physical RFQs
efpConvert to Physical requests, quotes and acceptance
deliveryPhysical contracts, acceptance decisions, escrow and attestation records
marketdataMarket and index data, limited to what your data tier includes (see Data access)

Signing a request

Send three headers. The signature is the hex HMAC-SHA256 of timestamp + METHOD + path_with_query + body, keyed with your secret. Requests more than 5 seconds from server time are rejected.

Signing
import hmac, hashlib, time, json
ts   = str(int(time.time() * 1000))
body = json.dumps(payload, separators=(",", ":"))
msg  = ts + "POST" + "/v1/orders" + body
sig  = hmac.new(secret.encode(), msg.encode(), hashlib.sha256).hexdigest()
headers = {"Authorization": f"Bearer {key}", "X-Timestamp": ts, "X-Signature": sig}
import { createHmac } from "node:crypto";
const ts = String(Date.now());
const body = JSON.stringify(payload);
const sig = createHmac("sha256", secret).update(ts + "POST" + "/v1/orders" + body).digest("hex");
const headers = { Authorization: `Bearer ${key}`, "X-Timestamp": ts, "X-Signature": sig };

Idempotency

Every POST, PATCH and DELETE accepts an Idempotency-Key header. Resending the same key within 24 hours returns the first result instead of acting twice. Order endpoints also reject a reused client_order_id among your open orders.

Contract specs

Compute Futures are cash-settled on Compute Signal indexes. The Node-Month Contract is the physical product you reach through an RFQ or Convert to Physical.

Unit1 GPU × 730 hours (1 GPU-month)8 GPUs × 730 hours (1 node-month) per lot

Tick$0.01/GPU-hr = $7.30 per contract$0.01/GPU-hr

Contract terms are proposals for review. Pull the live values from GET /v1/instruments; never hard-code tick, size or limits.

REST API

JSON over HTTPS. Base URL https://api.computedesk.example/v1. Prices are decimal strings, so they never lose precision. Times are ISO 8601 in UTC.

  • Pagination: list endpoints return {"data": [...], "next_cursor": "..."}. Pass cursor for the next page; limit is 100 by default and 1,000 at most.
  • Versioning: breaking changes get a new path version. Additive changes (new fields, new enum values) can arrive at any time, so ignore fields you don't know.

Block RFQ

One endpoint family covers two kinds of request. A block RFQ prices a large futures trade (25 contracts or more) off the screen. A physical RFQ asks providers to quote a Node-Month Contract against a term sheet. Requests are blind: providers see the term sheet, not who asked.

POST/v1/rfqsRequest quotes
Physical RFQ
{ "type": "physical",
  "term_sheet": { "chip": "H100", "gpus": 64, "region": "US-East", "interconnect": "InfiniBand",
                  "start_month": "2027-01", "term_months": 6, "sla_uptime": 99.5 },
  "price_type": "index_plus_basis", "max_basis": "0.15", "expires_in_s": 3600 }

For type: "block" send symbol, side (optional, to hide direction leave it out) and qty instead of a term sheet.

GET/v1/rfqs/{rfq_id}Status and quotes

Physical quotes come back normalised to the index reference spec, with a score that also weighs provider delivery history.

POST/v1/rfqs/{rfq_id}/quotesQuote (providers, market makers)

Send basis or price, qty and valid_for_s. Needs the rfq scope.

POST/v1/rfqs/{rfq_id}/acceptAccept a quote

Send quote_id. A block RFQ books a futures trade with venue: "block". A physical RFQ creates a contract in pending_escrow.

POST/v1/inventoryPublish capacity (providers)

Tell CDX which chips, regions and start months you can deliver, so physical RFQs and EFP requests are routed to you.

Convert to Physical (EFP)

Turn a futures position into a Node-Month Contract. CDX routes the request to qualified providers, you accept a basis quote, and two things book at once: your futures are bought back by the provider at the agreed futures price, and a physical contract is created at futures price plus basis.

Lots of 8. Physical delivery works in whole nodes, so qty must be a multiple of 8 contracts. One lot is one 8-GPU node for one month.

Keeping your book in sync

  1. Each channel has its own seq. Each delta's seq is one more than the last.
  2. If you see a gap, send {"op":"resync","ch":"book.H1UFZ26"}. You get a fresh snapshot, then deltas carry on from it.
  3. The server sends {"op":"ping"} every 15 seconds. Reply with pong within 10 seconds or the connection closes.
  4. Set "cancel_on_disconnect": true in auth to cancel your open orders if the connection drops.

You can place and cancel orders over the socket with {"op":"order.new", ...} and {"op":"order.cancel", ...}, using the same fields as REST. Responses come back on the orders channel.

FIX certification

Pass these scripted tests in Certification before we turn on a production session. Market makers also need a signed market maker agreement.

  1. Logon, heartbeat, test request and logout, including a bad signature that must be rejected.
  2. Sequence gap: we skip a number and you must send a ResendRequest and recover.
  3. Order lifecycle: new, partial fill, replace, cancel, and a reject for an off-tick price.
  4. Mass quote across 12 months, then a QuoteCancel for one month.
  5. Kill switch: OrderMassCancelRequest clears every order within 1 second.
  6. Cancel on disconnect: drop the connection and confirm orders are gone on reconnect.
  7. Circuit breaker: handle the 2-minute pause and resumption on the status feed.
  8. Drop copy (FCMs): receive and reconcile a block trade and an EFP.

Rate limits

Limits are per account. Responses carry X-RateLimit-Remaining and X-RateLimit-Reset. Going over returns 429 on REST, or a reject on WebSocket and FIX.
